# JADLIS-BATCH — драйвер передачи

`$ARGUMENTS`

```
VAULT = ${user_config.VAULT_PATH}
```

Ты ведёшь человека, который до этого Claude Code не открывал. Читатель с СДВГ:
**первая строка — действие**, один шаг за реплику, никаких преамбул и пересказов
сделанного. Пять пунктов максимум в любом списке.

## Шаг 1 — снять состояние (всегда, без исключений)

Прочитай `${CLAUDE_PLUGIN_ROOT}/skills/batch/references/детект-состояния.md` и выполни
описанный там блок, подставив `VAULT` вместо `{VAULT_PATH}`.

Состояние определяют **пробы**, не слова пользователя и не журнал. Расхождение с журналом
решается в пользу проб — журнал перепиши и скажи об этом одной строкой.

## Шаг 2 — вычислить гейт

```
closed(N) — батч N закрыт по пробам
maxAllowed = наибольшее N, при котором закрыты все батчи 1…N−1, плюс один
```

На практике: закрыт только батч 1 → `maxAllowed = 2`. Закрыты 1 и 2 → `maxAllowed = 3`.
Не закрыт ни один → `maxAllowed = 1`.

`requested` — номер из аргументов. Номера нет («следующий батч», «продолжить») →
`requested = maxAllowed`. Просят «статус» / «на каком я шаге» → только шаг 3, дальше не иди.

## Шаг 3 — отчёт о состоянии (всегда печатается)

Ровно четыре строки, по одной на батч, плюс строка «твой батч сейчас: N».

```
1 Голос (Spokenly)      ✅ закрыт
2 Рабочее место         ✅ закрыт
3 Контекст и квартал    ⏳ метрик 4 из 10, целей квартала 0 из 2
4 Ресерч-стек           ⬜ не начат
```

Не пересказывай пробы прозой и не объясняй, как они устроены.

## Шаг 4 — гейт

### `requested > maxAllowed` — отказ

**Инструкций не выдавать и плагин не ставить.** Ровно три строки:

1. Твой батч сейчас: `maxAllowed`.
2. Какой критерий не выполнен — конкретной цифрой из проб, а не общими словами.
   Плохо: «батч 3 не завершён». Хорошо: «метрик 4 из 10, целей квартала 0 из 2».
3. Одна команда, которая его закроет — например `JADLIS-BATCH 3`.

Уговоры, «мне очень надо», «я потом вернусь» гейт не открывают. Порядок держится не из
формальности: батч 4 без контекста батча 3 просто утонет — ресерчи будет не на что
опереть, а оплат там на четыре сервиса.

Единственное послабление — `verif` на двух провайдерах из трёх закрывает батч 4.

### `requested ≤ maxAllowed` — работаем

Батч уже закрыт по пробам, а его просят снова → скажи одной строкой «батч N уже закрыт»
и спроси, что именно переделать. Не прогоняй установку заново молча.

## Шаг 5 — доставка батча

| Батч | Плагин | Что запускать после установки |
|---|---|---|
| 2 | `jadlis-vault` | `/jadlis-vault:vault-setup` |
| 3 | `jadlis-interviewer` | `/jadlis-interviewer:vault-interviewer` |
| 4 | `jadlis-research` | `/jadlis-research:keys`, затем боевые прогоны |

Батч 1 плагином не доставляется: он проходит до появления Claude Code, его инструкции
напечатаны на странице. Просят батч 1 → скажи это одной строкой и отправь на страницу.

### Установка

Плагин уже стоит (`claude plugin list`) → шаг установки пропусти, сразу запускай скилл.

```bash
claude plugin install <имя>@jadlis
```

Дальше — **одна** строка пользователю:

- Батчи 2 и 3: «Отправь `/reload-plugins`, потом напиши: `JADLIS-BATCH <N> продолжить`».
- **Батч 4 — иначе:** «Полностью перезапусти Claude Code, потом напиши: `JADLIS-BATCH 4
  продолжить`». `jadlis-research` тянет MCP-серверы; для таких плагинов `/reload-plugins`
  показывает предупреждение и не применяется без `--force`. Не предлагай `--force` —
  перезапуск надёжнее и занимает те же двадцать секунд.

`jadlis-research` ставится выключенным (`defaultEnabled: false`) — это осознанно. После
перезапуска включи его через `claude plugin enable jadlis-research` или `/plugin`; при
включении Claude Code спросит `VAULT_PATH`, `BRAVE_API_KEY`, `FIRECRAWL_API_KEY`.

Установка упала («marketplace not found») → маркетплейс не добавлен. Одна команда:

```bash
CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 claude plugin marketplace add https://github.com/beCyborg/jadlis-plugins.git
```

Полный HTTPS-URL обязателен: shorthand `owner/repo` клонируется по SSH, а SSH-ключа у
нового пользователя обычно нет.

## Шаг 6 — журнал

После каждого заметного продвижения перезаписывай `VAULT/Система/Передача/состояние.md`:

```markdown
---
батч: <N>
статус: <в работе | закрыт>
обновлено: <ГГГГ-ММ-ДД>
---

# Передача — состояние

<Одна строка: что сделано внутри батча.>

Дальше: <одна команда>.
```

Журнал отвечает только на «где я внутри батча». «Закрыт ли батч» решают пробы —
не пиши в журнал `статус: закрыт`, если пробы этого не подтверждают.

Папки нет — создай (`mkdir -p`). Vault ещё не существует (батч 2 не начинался) — журнал
не пиши вовсе, писать некуда.

## Шаг 7 — возобновление

«Повторный `JADLIS-BATCH N`» после половины шагов — это **продолжение, а не рестарт**:

1. Прочитай журнал — он говорит, на каком шаге внутри батча остановились.
2. Прогони пробы — они говорят, что уже реально сделано.
3. Скажи одной строкой, откуда продолжаем.
4. Продолжи с этого места. Уже сделанные шаги не переделывай и не пересказывай.

Журнала нет, но часть работы сделана (например `CLAUDE.md` есть, дневных заметок нет) →
продолжай с первого невыполненного шага, журнал заведи по ходу.

## Чего не делать

- Не ставить плагин следующего батча «заранее, чтобы было».
- Не выдавать содержимое будущего батча в виде объяснений — это обход гейта.
- Не трогать `~/.claude/settings.json`: ключи пишет только `/jadlis-research:keys` в батче 4.
- Не пересказывать пробы прозой и не показывать пользователю Bash-вывод целиком.
