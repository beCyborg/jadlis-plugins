# Батч 2 — рабочее место: скелет vault, CLAUDE.md, первый перезапуск дня

```
VAULT      = ${user_config.VAULT_PATH}
ASSETS     = ${CLAUDE_PLUGIN_ROOT}/assets
```

Читателю с СДВГ: **один шаг за реплику**, первая строка — действие. Не вываливай весь
список сразу.

## Шаг 0 — где мы

```bash
V="${user_config.VAULT_PATH}"
echo "VAULT=$V"
[ -d "$V" ] && echo "папка есть" || echo "папки НЕТ"
[ -f "$V/CLAUDE.md" ] && echo "CLAUDE.md есть" || echo "CLAUDE.md нет"
ls "$V/Периоды/День/"*.md 2>/dev/null | wc -l | xargs echo "дневных заметок:"
[ -d "$V/.obsidian" ] && echo "Obsidian-vault инициализирован" || echo ".obsidian НЕТ — папка ещё не открыта как vault"
```

**Папки нет** — не создавай молча. Спроси: «Папки `<путь>` нет. Создать её здесь или ты
назвал vault иначе?» и жди ответа. Молчаливое создание не туда — самая дорогая ошибка
этого батча: дальше туда лягут все заметки.

**`.obsidian` нет** — папка существует, но Obsidian её ещё не открывал. Это **не повод
останавливаться**: скелет, `CLAUDE.md` и первый перезапуск дня от Obsidian не зависят.
Пропусти только шаг 3 (сниппет), сделай всё остальное, и в самом конце добавь одну строку:
«Открой папку в Obsidian как vault (Open folder as vault) и напиши `JADLIS-BATCH 2
продолжить` — доставлю сниппет `hide-files`». Ждать Obsidian, ничего не построив, — ровно
тот застой, ради борьбы с которым эта система и собрана.

Всё на месте — переходи к шагу 1. Часть шагов уже сделана (повторный запуск) — пропусти
их и скажи об этом **одной строкой**, не пересказывая.

## Шаг 1 — скелет папок

```bash
V="${user_config.VAULT_PATH}"
mkdir -p "$V/Потребности" "$V/Цели" "$V/Периоды/День" \
         "$V/Знания/Входящие" "$V/Знания/Ресерчи" \
         "$V/AI/verif" "$V/Система/Шаблоны" "$V/Система/Файлы" "$V/Система/Передача"
find "$V" -maxdepth 2 -type d -not -path '*/.*' | sed "s|$V|.|" | sort
```

Что где живёт:

| Папка | Что в ней |
|---|---|
| `Потребности/` | группы потребностей и метрики под ними (появятся в батче 3) |
| `Цели/` | `Цели/<год>-Q<квартал>/` — цели квартала (батч 3) |
| `Периоды/День/` | `<ГГГГ-ММ-ДД>.md` — дневные заметки |
| `Знания/Входящие/` | всё новое падает сюда |
| `Знания/Ресерчи/` | отчёты исследований (батч 4) |
| `AI/verif/` | вердикты верификаторов (батч 4) |
| `Система/Файлы/` | вложения |

`Смысл жизни.md` **не создавай** — эту заметку пишет интервьюер в батче 3, из твоих
собственных слов. Пустая заглушка тут только помешает.

## Шаг 2 — CLAUDE.md

Файл уже есть → **не перезаписывай**. Прочитай его, скажи «CLAUDE.md уже на месте» и
предложи показать, чем он отличается от шаблона. Решает пользователь.

Файла нет:

```bash
V="${user_config.VAULT_PATH}"
cp "${CLAUDE_PLUGIN_ROOT}/assets/CLAUDE.md.template" "$V/CLAUDE.md"
wc -l < "$V/CLAUDE.md" | xargs echo "CLAUDE.md строк:"
```

Скажи одной строкой, что в нём: карта vault, конвенции заметок и раздел «Как отвечать» —
правила ответа короткими шагами с конкретными оценками времени. Раздел действует всегда;
временно вернуть обычный стиль — фразой «normal mode».

## Шаг 3 — сниппет hide-files

`.obsidian` в vault нет → **шаг целиком пропусти** и иди на шаг 4. Вернёшься к нему, когда
пользователь откроет папку в Obsidian.

```bash
V="${user_config.VAULT_PATH}"
mkdir -p "$V/.obsidian/snippets"
[ -e "$V/.obsidian/snippets/hide-files.css" ] \
  && echo "сниппет уже есть — не трогаю" \
  || cp "${CLAUDE_PLUGIN_ROOT}/assets/hide-files.css" "$V/.obsidian/snippets/hide-files.css"
ls -1 "$V/.obsidian/snippets/"
```

Дальше — руками пользователя, файл сам себя не включит:
**Settings → Appearance → CSS snippets → включить `hide-files`** (если списка нет — кнопка
🔄 рядом с ним).

## Шаг 4 — первый перезапуск дня

Это и есть критерий батча: скелет без единой заметки — пустая папка, а не система.

1. Спроси через AskUserQuestion: «Три итога сегодняшнего дня — что получилось?» Достаточно
   коротких формулировок; можно надиктовать.
2. Помоги выбрать **до 5** задач на завтра. Больше пяти — попроси выкинуть лишнее, а не
   переноси всё.
3. Создай завтрашнюю заметку:

```bash
V="${user_config.VAULT_PATH}"
D=$(date -v+1d +%F 2>/dev/null || date -d tomorrow +%F)
echo "$V/Периоды/День/$D.md"
```

Формат заметки (Write, Obsidian-flavored Markdown):

```markdown
---
type: day
date: <ГГГГ-ММ-ДД>
---

# <ГГГГ-ММ-ДД>

## Задачи

- [ ] …

## Итоги

## Заметки
```

Сегодняшнюю заметку с тремя итогами создай тем же форматом, заполнив «Итоги».

## Шаг 5 — журнал и передача дальше

```bash
V="${user_config.VAULT_PATH}"
cat > "$V/Система/Передача/состояние.md" <<EOF
---
батч: 2
статус: закрыт
обновлено: $(date +%F)
---

# Передача — состояние

Батч 2 закрыт: скелет разложен, CLAUDE.md на месте, первый перезапуск дня прошёл.

Дальше: напиши \`JADLIS-BATCH 3\` — интервью, из которого появятся смысл жизни,
потребности с метриками и цели квартала.
EOF
echo "журнал записан"
```

Закончи ровно двумя строками:

1. Что теперь работает: «Claude Code читает и пишет заметки в vault, завтрашняя заметка
   создана».
2. Следующее действие: «Напиши `JADLIS-BATCH 3`, когда вечерний ритм продержится хотя бы
   несколько дней — интервьюеру нужен живой контекст, а не пустой vault».

## Чего в этом батче не делать

- Не ставить `jadlis-interviewer` и `jadlis-research` — их ставит драйвер по своему гейту.
- Не заполнять `Потребности/` и `Цели/` — это работа интервьюера в батче 3.
- Не трогать `~/.claude/settings.json` — ключи появляются только в батче 4.
